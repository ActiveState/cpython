Fix a hang in tarfile streaming mode (CVE-2026-11972)

Seeking forward in a :mod:`tarfile` stream opened in ``r|`` mode stopped
only at the target offset, so a member header declaring a huge size made it
loop forever at end of file. It now stops at EOF and raises
:exc:`tarfile.ReadError` ("unexpected end of data").

The regular expression :class:`csv.Sniffer` uses to guess the quote character

Reject malformed Content-Length and chunk sizes in httplib (CVE-2026-103995)

:mod:`httplib` now accepts only decimal digits (with optional surrounding
whitespace) in ``Content-Length``, and only hexadecimal digits for a chunk
size. Values such as ``+5``, ``-0`` or ``0x10``, which other HTTP
implementations parse differently, are rejected or ignored instead of being
used.

Limit what httplib reads around interim responses and trailers (CVE-2021-3737)

:class:`httplib.HTTPResponse` now reads at most 100 header lines inside a
``100 Continue`` response, skips at most 100 interim (1xx) responses, and
discards at most 100 trailer lines after a chunked body
(GHSA-w4q2-g22w-6fr4). Each limit raises :exc:`httplib.HTTPException` when
exceeded, instead of reading for as long as the server keeps sending.

Fix quadratic time in HTMLParser incremental parsing (CVE-2026-15308)

:class:`HTMLParser.HTMLParser` copied its whole buffer on every
:meth:`~HTMLParser.HTMLParser.feed` call while a construct was still open,
so feeding a document in small pieces was quadratic. Data is now buffered
until it can be parsed. As upstream, events after such a construct may be
reported later, but none are lost.

Fix a use-after-free in the ssl SNI callback (CVE-2026-19445)

A servername callback that switched the connection to another
:class:`ssl.SSLContext` while the original context was released could make
the next callback read freed memory and crash the server. The callback now
finds its context through the connection and keeps it alive while in use.
After a switch, later ClientHello messages go to the new context's
callback.

Use the Winsock values for socket errno constants on Windows

Visual Studio 2010 and later define their own ``ECONNRESET``,
``EWOULDBLOCK``, ``ETIMEDOUT`` and other socket error numbers in
``errno.h``, but Windows sockets report the Winsock ``WSAE*`` codes, so
``errno.EWOULDBLOCK`` (140) never matched a socket error (10035). The
:mod:`errno` module now uses the Winsock values for these 25 constants, as
Python 3.5 and later do.
